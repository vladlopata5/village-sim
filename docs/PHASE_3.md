# Phase 3 — распорядок дня

Статус: начат, реализовано только текущее занятие. Phase 2 завершён; ResidentIntent и NightHomeController послужили ранней основой этого этапа. F6/F7/F8 остаются временными инструментами разработки.

ResidentIntent — что житель хочет сделать (цель и приоритет). ResidentActivity — что он сейчас делает. scripts/resident_activity.gd содержит enum Type: IDLE / MOVING / SLEEPING. ResidentData.activity хранит одно значение, изначально IDLE; без координат или визуальных ссылок.

ResidentIntentController.setup(data) получает исходные данные. Принятие MOVE_TO устанавливает MOVING. Подтверждённое прибытие очищает намерение и устанавливает IDLE, затем испускает intent_completed. NightHomeController слушает этот сигнал: прибытие по night_home ночью меняет занятие на SLEEPING. Отмена намерения и устаревшее завершение не вызывают сон. В 06:00 незавершённый путь домой очищается до IDLE, спящий также становится IDLE. Утренней автоматической цели нет.

Карточка читает ResidentData.activity и показывает «Бездельничает», «Идёт», «Спит». На паузе принятое движение остаётся MOVING, но позиция не меняется. Сон не изменяет усталость, голод или настроение. Работа, еда, социальное поведение, новые автоматические решения и остальные части распорядка пока отсутствуют.

Проверка: F5 → выбрать Степана → IDLE («Бездельничает»). Правый клик → MOVING («Идёт»), прибытие → IDLE. F8 до 23:00 → MOVING к дому → SLEEPING («Спит»), F8 до 06:00 → IDLE. Если нажать F8 до утра ещё в пути, движение прекращается и становится IDLE. Повторить на паузе и x1/x2/x4; состояния остаются 20/35/65.

Автоматическая проверка: tests/test_resident_activity.gd, а также все существующие tests/test_*.gd через Godot --headless --path проекта --script res://tests/<имя>.gd.


## Дом как игровое место

WorldLocation (scripts/world_location.gd) — независимые данные: стабильный id и display_name. Main создаёт единственное тестовое место home_stepan / «Дом Степана». ResidentData.home_location_id хранит только ID этого места.

WorldLocationView2D на прежнем голубом HomePoint получает WorldLocation и показывает его название. Координаты (-300, -120) остаются только размещением маркера сцены. WorldLocations2D сопоставляет данные места с визуальным узлом и возвращает его актуальную global_position по ID; отсутствующее место/удалённое представление возвращает null, без подстановки (0, 0).

В 23:00 NightHomeController читает home_location_id из ResidentData, запрашивает текущую позицию у переданного механизма мира и создаёт прежний night_home. Домашних координат в контроллере нет. Прибытие → SLEEPING, 06:00 → IDLE, дневные ручные команды сохранены. Позиция разрешается в момент команды; движение уже выданной цели не отслеживает перемещение маркера.

При переходе к 3D WorldLocation и home_location_id сохранятся. Заменятся сопоставление с представлением и пространственная часть MOVE_TO/исполнителя на Vector3. Система 3D сейчас не реализуется.

Проверка: обычный ночной сценарий через F8; также перед запуском можно передвинуть HomePoint в редакторе — Степан пойдёт к новому положению без изменения данных или NightHomeController. tests/test_world_location.gd проверяет идентичность, актуальную позицию маркера, замену представления, отсутствующее место и полный ночной сценарий.
