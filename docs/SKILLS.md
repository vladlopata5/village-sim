# Навыки жителей

## Единая модель

ResidentData хранит единственный словарь Skill.Type → integer XP. Все 15 навыков
нового жителя начинаются с нуля; старый опыт не импортируется и не распределяется.
Профессия и её смена не сбрасывают уже заработанный опыт нового жителя.
Старые числовые уровни 0–10 удалены, совместимого get_skill_level нет.

Навыки: Строительство, Лесное дело, Горное дело, Собирательство, Земледелие,
Животноводство, Логистика, Деревообработка, Камнеобработка, Гончарное дело,
Ткачество, Портняжное дело, Мельничное дело, Кулинария, Ремесло.
Имена и enum находятся в scripts/skill_type.gd. XP ограничен 0..10000.

| Звание | XP включительно |
|---|---:|
| Профан | 0–399 |
| Новичок | 400–999 |
| Любитель | 1000–1799 |
| Опытный | 1800–2999 |
| Мастер | 3000–10000 |

Предел и пороги заданы в BalanceConfig. get_skill_rank вычисляет звание из XP;
отдельного изменяемого звания нет. Карточка показывает название навыка и звание,
без числового XP и индекса звания. DEBUG сохраняет фактический XP и delta.
Звания не дают самостоятельных бонусов.

## Чистая эффективность

Skill.efficiency_percent(xp) = 100 + 50 × sqrt(XP / 10000).
Результат — процент с дробной частью: 0 → 100%, 400 → 110%, 2500 → 125%,
10000 → 150%. Для нескольких навыков усредняются их проценты с весами,
а не сначала XP. Расчёт не использует RNG, не изменяет жителя и не кэшируется.
В S3 расчёт подключён только к активному рабочему объёму; движение и AI не ускоряются.

## Правила операций

WorkSkillRules — небольшой набор данных с независимыми списками:

- requirements: {skill, min_xp}. Все перечисленные минимумы обязательны.
- efficiency_weights: {skill, weight_percent}. Положительные целые проценты,
  сумма ровно 100. Пустой список означает отсутствие влияния навыков, 100%.
- xp_rewards: {skill, amount, training_cap}. Положительная целая награда и
  неотрицательный предел обучения для неё.

Навыки требований, эффективности и наград могут различаться. В одном списке один
навык указывается один раз: повторы, неизвестные ID, лишние/пропущенные поля,
неправильные типы и неверная сумма весов отклоняют весь набор. Входные массивы
копируются; данные проверяются при каждом запросе, включая последующее изменение.

validation_errors возвращает диагностику. can_perform, efficiency_percent и
reward_deltas — чистые запросы; при некорректном наборе возвращают false, -1 и {}
соответственно. -1 не является нейтральной эффективностью: ошибочный набор нельзя
использовать. Отсутствующий житель также отклоняется. Потребитель будущей операции
сам проверяет допуск; получение награды не запускает работу и не проверяет её
успех задним числом.

Для награды actual_delta = min(amount, max(0, min(10000, training_cap) − current)).
Предел ниже текущего XP не уменьшает накопленное. Предел выше 10000 не обходит
общий cap. Сначала ограничивается delta, затем выполняется сложение, поэтому даже
запрос int64-max не переполняет XP. Предел одной операции не ограничивает обучение
другими операциями. Нулевая фактическая награда не вызывает сигналов.

ResidentData.add_skill_xp(skill, amount, training_cap=10000) начисляет одному навыку.
award_skill_xp(rules) применяет все допустимые награды: сначала весь XP и снимки
повышений, затем уведомления. false означает отказ или отсутствие фактических
начислений. Проверка rules и расчёт deltas не публикуют callbacks и не дают
частичных начислений при ошибке в одной строке.
Повторный вызов award_skill_xp — самостоятельное начисление; он не хранит историю
выполненных заданий. Защита от повторного завершения остаётся у владельца операции,
как в действующих контроллерах и receipts. S1 не вводит второй журнал заданий.

## События и вложенные callbacks

skill_changed(skill, actual_delta, previous_rank) сообщает фактическое изменение XP.
skill_raised(transition_id, skill, previous_rank, new_rank) означает повышение звания.
Скачок через несколько званий одной наградой даёт один факт со снимками начального
и конечного звания. Все факты публикуются FIFO по commit после внешних skill_changed;
вложенные начисления не переименовывают предыдущие переходы и не повторяют их.

GameEventService сохраняет идентичность occurrence, проверки активности, дедупликацию,
cooldown и атомарные последствия. Новый payload: skill, skill_name, previous_rank,
new_rank, previous_rank_name, new_rank_name. Старых previous_level/new_level нет.
Числа Rank 0..4 — внутренние упорядоченные коды званий, не вторая система уровней.
Социальные facts используют skill.rank и skill.name.

Обычная история personal.skill_progress подходит для любого повышения звания.
По решению пользователя особая personal.skill_progress_advanced доступна с «Любителя»
и выше; она конкурирует с обычной в одном выборе, не запускается дополнительно.
Зависть сравнивает звания в том же навыке и требует прежнюю активную чужую гордость.
Восхищение продолжает реагировать на подтверждённую гордость. JSON-ревизии затронутых
историй повышены; вероятности, cooldown и социальные реакции не перебалансированы.

## S2 — награды реальных операций

scripts/work_operation_skills.gd — единый набор данных WorkSkillRules для действующих
операций. Контроллеры вызывают award_skill_xp только после своего подтверждённого
завершения. Старые +1 и флаг HaulJob.award_logistics_xp удалены. Универсального
завершения по признаку WORK или по выпуску каждой единицы продукта нет.

| Операция | Награда | Предел обучения |
|---|---|---|
| Личный полный строительный цикл 60 минут, включая демонтаж/улучшение | Строительство +8 | 10000 |
| Рубка дерева | Лесное дело +8; Деревообработка +2 | 10000; 1000 |
| Посадка с успешным созданием саженца | Лесное дело +4 | 10000 |
| Добыча единицы камня | Горное дело +8; Камнеобработка +2 | 10000; 1000 |
| Добыча единицы глины | Горное дело +8 | 10000 |
| Полный рейс природного гриба в хижину | Собирательство +3, без дополнительной Логистики | 10000 |
| Обработка/посев/скашивание одной клетки | Земледелие +1 | 10000 |
| Отлов с сопровождением и приёмом овцы | Животноводство +8 | 10000 |
| Успешная полная стрижка 120 минут | Животноводство +16 | 10000 |
| Доставка, включая COLLECT/SUPPLY/IMPORT/EXPORT, воду/топливо, подвоз строителем | Логистика +3 независимо от профессии/расстояния | 10000 |
| sawmill_plank / cut_stone_brick / fire_brick, партия 30 минут | Профильный +3; Ремесло +1 | 10000 каждому |
| wool_cloth / mill_flour, партия 60 минут | Профильный +6; Ремесло +2 | 10000 каждому |
| wool_clothing, партия 120 минут | Портняжное дело +12; Ремесло +4 | 10000 каждому |
| fried_mushroom / bake_bread, партия 30 минут | Кулинария +4 | 10000 |
| thresh_wheat, партия 30 минут | Земледелие +4 | 10000 |

Все минимальные требования XP равны нулю (пустой requirements); правила ресурсов,
профессий, claims/слотов и расписания сохраняются. Рубка зависит только от Лесного
дела, добыча камня/глины — только от Горного дела; вторичные награды не становятся
весами эффективности. Шесть ремесленных направлений имеют профильные 80% +20%
Ремесла; остальные — профильные 100%. Эти веса подготовлены, но **не применяются
к скорости труда в S2**. Подключение S3 описано ниже; требования объёма, выходы,
пути и AI сохраняются.

Партия, дерево или месторождение сохраняют свой прежний прогресс. При смене
исполнителя полную награду получает завершивший; XP за вклад не накапливается.
Строительство — отдельное правило: только свои полные 60 минут, без награды за
здание/стадию/малый остаток. Перенос материалов не входит в эти 60 минут, но его
завершённая доставка получает Логистику. Поле награждается за клетку, не за всю
очередь из пяти; уже законченные клетки не теряют XP при отмене остатка.

Прерванная стрижка не награждается даже при частичной шерсти или при settle на
границе 120 минут. Полный успешный цикл награждается независимо от случайного
выхода/переполнения. MOW с нулевым случайным урожаем остаётся успешной клеткой.
Количество продуктов и необязательная солома не умножают XP партии.

Начало/подбор/погрузка сами XP не дают. Штатная выгрузка излишка на землю с PLACED
или разрешённым DISCARDED закрывает рейс и даёт +3; FAILED и аварийный сброс при
cancel — нет. Один груз воды/бревно топлива даёт одну награду, не пять по числу
расходных единиц. Переназначение профессии не переадресует награду рейса.
Инструменты, бонусы черт/мудлетов и save/load в этот этап не входят.

## S3 — эффективность активной работы

ResidentModifiers.work_rate читает готовый WorkSkillRules и возвращает коэффициент
1..1.5. Неверный набор/житель отклоняется, а не заменяется нейтральной скоростью.
Контроллер фиксирует коэффициент при начале активной операции или её возобновлении.
Изменение XP внутри операции не пересчитывает её скорость; новый исполнитель или
новая операция получает новый снимок. Вес и формула не дублируются в исполнителях.

Стандартный объём хранится обычным float у прежнего владельца: здание, партия,
дерево, цикл месторождения, локальная клетка/посадка/отлов или ResourceHandling.
WorkProgress ограничивает вклад и сравнивает порог с абсолютным допуском 1e-8.
Достижение порога нормализуется точно к требуемому объёму; демонтаж — к нулю.
Завершение проверяется на целой игровой минуте. Избыток не переходит в следующую
операцию или через границу строительной стадии. Частичная шерсть рассчитывается
по дробному объёму с прежними floor выхода и ceil снятых уровней.

60 стандартных минут при100/125/150% требуют60/48/40 активных игровых минут.
Для10 стандартных минут —10/8/7. Перемещение, очередь COURIER, ожидание материалов,
claims, календарный рост/сезоны и GameTime не получают коэффициент навыка.

Строитель хранит отдельные целые личные work_minutes. За60 фактических активных
минут он вносит60/75/90 стандартных минут и получает прежние+8 XP. Последний
принятый, даже обрезанный тик считается одной личной минутой; отвергнутый вклад
не засчитывается. Незавершённый личный цикл не переносится в новое задание.
Несколько строителей прибавляют независимые вклады в один прогресс здания.

Оплаченная партия/дерево/месторождение сохраняют дробный вклад при смене работника.
PLANT, полевая клетка, отлов и handling теряют незавершённый локальный объём по
прежним правилам отмены. Стрижка при cancel сохраняет только результат partial
settle, без XP. Её result.minutes — стандартный выполненный объём, не elapsed.

Обычные loading/unloading используют Логистику, включая доставку строителем,
воду и топливо. NATURAL_MUSHROOM loading использует gather_loading/Собирательство;
его unloading — Логистику. Это не меняет единственную награду рейса Собирательства.
Стадия handling поглощается до callbacks передачи; cancel обнуляет её прогресс.

Все награды S2 и ограничения обучения сохранены. Более быстрые завершения могут
давать больше XP за календарный день, но награда одной операции не умножается.
HASTY умножает эту навыковую скорость ×1.15 при старте/возобновлении активной
операции (до ×1.725 при максимальных навыках). Включён непосредственный сбор
гриба gather_loading; обычные loading/unloading сохраняют только навыки. Прочие
черты, настроение и инструменты к рабочей скорости пока не подключены.
