# Phase 2 — техническая основа одного жителя

Реализованы техническая основа одного жителя, выбор кликом, простая информационная карточка, базовые черты характера, текущие состояния, временное ручное перемещение одна тестовая реакция на ночь и общий механизм текущего намерения.

## Данные и представление

scripts/resident_data.gd — обычный RefCounted с полями id, resident_name, age, profession, списком traits и состояниями hunger, fatigue, mood. Он не является узлом сцены и не хранит ссылку на графику или координаты.

Главная сцена хранит resident_data и при запуске создаёт тестового жителя:
- ID: resident_001 (уникален среди жителей текущего прототипа);
- имя: Степан;
- возраст: 30;
- профессия: Без профессии;
- известные черты: Трудолюбивый, Общительный, Упрямый;
- голод: 20, усталость: 35, настроение: 65.

ID назначает код, создающий жителя. Сейчас житель ровно один; сохранение и генератор ID для будущего населения не реализованы.

scenes/resident_view_2d.tscn и scripts/resident_view_2d.gd — временное изображение. setup(data) получает ссылку на существующего жителя; поля не копируются и не создаются в представлении. Положение (120, 80) задаётся только визуальному узлу.

Удаление изображения не удаляет данные из главной сцены. Будущее 3D-представление сможет получить тот же объект данных. Добавлены ручное перемещение и фиксированная команда идти домой ночью. Полноценный распорядок и AI не реализованы.

## Выбор и карточка

ResidentData → ResidentView2D → ResidentSelection → ResidentCard.

- ResidentView2D получает данные через setup(data). Клик по телу или голове вызывает selection_requested(data); координаты учитывают положение камеры.
- Main соединяет этот сигнал с ResidentSelection.select(data).
- ResidentSelection.selected_resident — единственное место хранения текущего выбора; это ссылка на ResidentData, без ссылки на визуальный узел.
- ResidentCard получает узел выбора и читает его selected_resident. Карточка выводит имя, возраст, профессию, ID, известные черты и текущие состояния; собственной копии полей жителя нет. Пока карточка открыта, текст обновляется из исходных данных.
- «Закрыть» очищает выбор. Необработанный клик по пустому месту внутри временного поля также очищает выбор. Клик по UI не проходит на поле.
- Выбор и карточка работают на паузе. ResidentView2D обрабатывается всегда для ввода; движение отдельно проверяет паузу и не выполняется во время неё.
- ResidentData не знает о выборе, UI или изображении. Будущий 3D-объект сможет передавать тот же ResidentData в ResidentSelection.select(data).

## Базовые черты характера

scripts/trait_data.gd определяет Resource TraitData с двумя полями:
- id: стабильный StringName для идентичности черты;
- display_name: название для отображения.

Три определения находятся в assets/traits/:
- hardworking.tres: hardworking → Трудолюбивый;
- sociable.tres: sociable → Общительный;
- stubborn.tres: stubborn → Упрямый.

ResidentData.traits — типизированный Array[TraitData]. Каждый житель имеет собственный список ссылок на определения. Определения могут использоваться несколькими жителями; название относится к определению, а не к UI. Переименование display_name не меняет id. Назначает черты Main при создании тестового Степана.

Карточка читает список и названия непосредственно из выбранного ResidentData. UI не хранит свою копию списка и не содержит таблицу названий черт. При пустом списке отображается «Известные черты: нет». Сейчас все назначенные черты известны; механизма скрытых черт нет.

Позже в определение можно добавить эффекты, а список жителя менять по событиям жизни. AI сможет распознавать черты по ID без разбора текста. Будущую скрытость следует хранить отдельно для конкретного жителя, не изменяя общее определение. Эти будущие механизмы пока не реализованы.

## Текущие состояния

Состояния хранятся прямо в ResidentData: hunger, fatigue, mood — целые числа 0–100. Присваивание ограничивается диапазоном через setter и clampi. Стартовые значения Степана: 20, 35, 65. Состояния не зависят от UI, визуального узла или черт характера и не меняются автоматически.

scripts/resident_state_text.gd преобразует числа в текст только для представления. Ни ResidentData, ни будущая симуляция не должны разбирать эти строки.

| Диапазон | Голод | Усталость | Настроение |
| --- | --- | --- | --- |
| 0–24 | Сыт | Отдохнувший | Очень плохое |
| 25–49 | Немного голоден | Немного устал | Плохое |
| 50–74 | Голоден | Устал | Хорошее |
| 75–100 | Очень голоден | Очень устал | Отличное |

Высокие голод и усталость означают более сильные состояния. Высокое настроение означает лучшее настроение. Порогам пока не соответствуют игровые последствия.

Карточка читает числа выбранного ResidentData и показывает число вместе с описанием. show_state_numbers в ResidentCard — настройка представления: false оставляет только описание. Это не изменяет данные и не добавляет переключателя в игровой интерфейс.

Позже события, действия и система времени смогут изменять эти же поля; AI сможет читать числа. Сейчас питание, сон, автоматические изменения, последствия и AI отсутствуют.

## Временное ручное перемещение

Принятое намерение хранится в ResidentIntentController.current_intent. ResidentView2D.apply_intent(intent) получает его и вызывает move_to(world_target) для исполнения. Цель — глобальные координаты временного 2D-представления; view.target_position хранит исполняемую точку, а has_movement_target показывает наличие движения. Текущая позиция остаётся свойством Node2D.global_position, без добавления координат в ResidentData.

Main принимает необработанный правый клик внутри поля, преобразует координаты с учётом Camera2D и передаёт точку в NightHomeController.request_manual_move(), который вне ночи создаёт MOVE_TO с причиной manual_move и отправляет его в ResidentIntentController. Без выбора команда не выдаётся. Клик по UI или вне поля не меняет цель. Вне ночной фазы повторный правый клик заменяет цель, сохраняя выбор и карточку; ночью действует приоритет домашней цели.

Движение выполняется прямо к цели через move_toward: 120 пикселей за секунду на x1, 240 на x2, 480 на x4. Каждый шаг учитывает delta и множитель, переданный через GameTime.speed_changed. Engine.time_scale не меняется. Диагональное движение имеет ту же скорость, а прибытие прекращает движение без перелёта.

На паузе _process не перемещает жителя и не накапливает время движения. Вне ночной фазы ручную цель можно изменить на паузе; движение начнётся после продолжения. Снятие выбора закрывает карточку, но уже выданная команда продолжает выполняться.

Метод команды отделён от обработки мыши: позже его сможет вызывать другой источник решений. При переходе к 3D заменяются представление, координаты и преобразование клика, но данные жителя и выбор сохраняются. Это временное визуальное перемещение; общая пространственная модель симуляции сейчас не создаётся. AI, NavigationAgent2D, препятствия, работа и изменение состояний отсутствуют.

## Тестовая реакция на ночь: идти домой

Дом — временный Marker2D Main/World/HomePoint в точке (-300, -120). Голубой ромб с подписью «Дом Степана» отмечает точку; это не здание и не новый объект симуляции.

Отдельный Node Main/NightHomeController (scripts/night_home_controller.gd) слушает GameTime.phase_changed. Main передаёт ему координаты маркера и ResidentIntentController в setup(). NightHomeController создаёт намерение и отправляет его контроллеру; прямой связи с ResidentView2D больше нет. Сам контроллер не зависит от UI или визуального узла, а ResidentData не меняется.

- В 23:00 фаза «Ночь» создаёт MOVE_TO с причиной night_home, целью home_position и приоритетом 100. Контроллер заменяет предыдущее ручное намерение независимо от выбора/карточки.
- При прибытии move_toward останавливает движение; view передаёт завершённое намерение контроллеру, который очищает его до NONE.
- request_manual_move() отклоняет команды во время ночи, в том числе после прибытия и на паузе. В полночь ночной приоритет сохраняется.
- В 06:00 ночной приоритет снимается. Ручные команды снова разрешены; новой автоматической утренней команды нет. Если путь домой ещё не завершён, существующая цель сохраняется, но её приоритет снижается до 0: новая ручная команда может заменить её.
- При создании контроллера ночью домашняя команда выдаётся сразу.
- Пауза и x1/x2/x4 используют существующие правила движения: на паузе цель сохраняется, движение продолжается без накопления пропущенного времени.

Это единственная фиксированная реакция на смену времени, без сна, изменения состояний, выбора действий AI, системы задач, работы или зданий. Остальные части распорядка ROADMAP не реализованы.

## Текущее намерение жителя

Цепочка: источник решения → ResidentIntent → ResidentIntentController → ResidentView2D.

- scripts/resident_intent.gd — обычный RefCounted. Только два типа: NONE и MOVE_TO. MOVE_TO содержит reason_id, target_position и priority. Он не содержит Node, UI или ResidentData; целевая Vector2 пока соответствует временному 2D-прототипу.
- scripts/resident_intent_controller.gd — отдельный Node. current_intent — единственное место хранения текущего принятого намерения. Нет очереди задач или выбора действий AI.
- NightHomeController — источник ночного намерения (night_home, 100). Его request_manual_move — вход ручной тестовой команды (manual_move, 10), с запретом ручного ввода ночью даже после завершения домашнего намерения.
- submit() принимает первое намерение при NONE или намерение с более высоким приоритетом. Более низкий приоритет и равный приоритет другого источника отклоняются.
- Намерение с тем же reason_id и равным приоритетом может обновить цель: это сохраняет повторные правые клики. Для обновления принимается новый объект намерения, чтобы отличать его завершение от старого.
- intent_changed передаёт принятое намерение в view.apply_intent. Изображение не выбирает намерение и не решает приоритеты.
- После достижения цели view.intent_completed передаёт конкретный объект принятого намерения. clear_completed() очищает current_intent только если это всё ещё тот же объект. Запоздалое завершение вытесненной цели не может очистить новую.
- Если житель уже находится в целевой точке, намерение завершается сразу. NONE прекращает исполнение и обозначает отсутствие текущего намерения; оно не используется как команда вытеснения через submit().
- В 06:00 release_priority(night_home) снимает приоритет незавершённого домашнего намерения, не отменяя путь. Ручная команда с приоритетом 10 снова может его заменить. После прибытия текущее намерение уже NONE.

ResidentData не изменён: пространственных координат, намерений или ссылок на сцену в нём нет. Пауза и скорость движения по-прежнему относятся к исполнителю. Дополнительные типы намерений, работа, потребности и AI этим рефакторингом не добавлены.

### Проверка намерений
