# Настроение и мудлеты потребностей

Актуальный контракт:2026-11-02. Настроение не имеет самостоятельной динамики.

```
mood = clamp(50 + сумма mood.offset активных мудлетов, 0, 100)
```

ResidentData.mood — производное read-only число, без отдельного сохранённого
начального настроения. Дробные offsets допустимы; расчёт не округляет их. Карточка
сохраняет прежние описательные диапазоны; отладочное число выводится до2 знаков.
Factory больше не принимает initial mood. Генератор не присваивает случайное
настроение, но расходует прежний RNG draw без использования его значения, чтобы
не сдвигать последовательность имён, возраста, черт и предпочтений следующих жителей.

## Числовые каналы

MoodletStore остаётся единственным источником записей. ResidentModifiers валидирует
и рассчитывает общий агрегат двух поддерживаемых каналов:

- `{"channel":"mood.offset","value":-10}` — сложение конечных signed чисел.
- `{"channel":"need_growth_rate","need":"hunger","multiplier":0.5}` — прежнее
  умножение только положительного роста дефицита, без изменения восстановления.

Один record может содержать оба канала. Неизвестные старые каналы (включая `mood`
без `.offset`) остаются данными без исполнения. Обновление типа заменяет один
record целиком, не складывает длительности/числовые вклады. angry/pride/well_fed
и прочим существующим типам новые offsets автоматически не добавлялись.

## Кэш, время и уведомления

Общий cache MoodletStore хранит factors и mood_offset, ближайшую границу активации/
истечения. Он перестраивается при мутации либо достижении этой границы, не каждый
тик. `_rebuild_numeric_cache` заменяет старое имя `_rebuild_growth_cache`; второго
агрегатора/хранилища нет. Чтение need_growth_factors возвращает копию для всего
минутного обновления потребностей. Чтение mood использует этот же кэш.

Runtime и GameEventService связывают Store с существующим GameTime через слабую
ссылку для чтения времени. Это не подписка Store на часы. Runtime.advance перед
собственными schedule/needs/work callbacks удаляет просроченные записи и проверяет
ближайшую числовую границу. Не требуется новый Timer, Scheduler, обход всех жителей
или дополнительный process. При чтении чужого жителя до его минутного callback
учитывается уже текущее время GameTime — просроченный offset не попадает в событие.
Без привязанных часов автономные данные используют последнее явно прочитанное/
переданное Store время (изначально0).

Store.changed сохраняет прежний смысл изменения записи. modifiers_changed сообщает
о смене действующих числовых коэффициентов/итогового настроения. Молча применяемые
событийные writes лишь инвалидируют кэш; его уведомления идут через прежний
post-commit changed, после завершения всего события и записи летописи. Будущая
активация/истечение обрабатываются локальной минутной границей. Карточка подписана
на изменения и отключается при смене жителя/уничтожении; пол не выводится из имени.

## Четыре гарантированных состояния

`need_moodlet_rules.gd` — данные четырёх правил, не сюжетные JSON-определения:

| Need | ID | Мужская / женская форма | Эффект |
|---|---|---|---|
| HUNGER | hungry | Голодный / Голодная | mood.offset−10 |
| FATIGUE | exhausted | Измотанный / Измотанная | mood.offset−10 |
| SOCIAL | lonely | Одинокий / Одинокая | mood.offset−10 |
| LEISURE | bored | Скучающий / Скучающая | mood.offset−10 |

Состояние выдаётся при дефиците строго>90, удаляется строго<40. Включительный
диапазон40…90 сохраняет прежнее наличие. Записи бессрочные, без повторного add/
refresh при сохранении состояния. Каждое изменение конкретного Need.value вызывает
проверку только его правила. Это включает рост, еду, сон, REST, TALK и LEISURE,
ручные тестовые/отладочные изменения и исходные значения Factory. Все4 состояния
дают настроение10; восстановление3 из них вернёт40, всех4 —50.

ResidentData.need_state_changed публикует frozen domain context с trigger ID
`need.state_changed`, actor ref, sequence occurrence ID, minute и payload
`{need,active,deficit,moodlet}`. Очередь сохраняет порядок вложенных изменений.
Гарантированная запись/удаление Store выполнены до публикации факта. Неизменное
состояние не публикует новый факт. Наличие состояния берётся из того же MoodletStore,
отдельной копии bool-флагов нет.

Это **доступный будущим историям доменный факт**, а не исполненное сюжетное событие.
GameEventService пока не подписан на него, Catalog не содержит таких историй и
selector не расходует RNG. Ничего не попадает в летопись/Diary/чат автоматически.
Когда потребуется история на переходе, можно подключить этот источник обычным
адаптером GameEventService; гарантированные изменения не зависят от её выбора.
Нового EventEngine или механизма сюжетных последовательностей нет.

## Совместимость

Числовой факт mood в ResidentEventFacts теперь получает производное значение.
Прежняя Ссора допускается при3/4 активных штрафах (mood20/10), если выполнены её
собственные условия; её30%, вес, cooldown и последствия не изменены. angry по-прежнему
только открывает VENT_ANGER, well_fed только замедляет рост HUNGER. pride участвует
в условиях историй зависти/восхищения, не повышая настроение. Новых историй нет.

## Приятная компания (2026-11-02)

`pleasant_company` — временный положительный мудлет от social.warm_sympathy
и положительной стороны social.awkward_conversation.
В social.warm_sympathy один50%-бросок выдаёт обоим участникам по записи на120 игровых минут с mood.offset+10.
В target хранится второй участник, название — context.display_name «Приятная компания».
Это стандартный описатель числового эффекта, без проверки типа в NeedDynamics/AI.
Базовый mood50 становится60; остальные активные offsets суммируются по прежнему правилу.
Повторная выдача обновляет единственную запись, не накапливает +10; expiry снимает
вклад через прежний локальный кэш. Отдельного изменения отношений не начисляется.

В social.awkward_conversation каждый участник имеет независимый30%-пакет личной
записи и мудлета. Положительная сторона получает прежний pleasant_company(+10),
отрицательная — awkwardness «Неловкость»(−10), оба на120 игровых минут. Повторная
выдача любого типа обновляет его единственную запись до now+120; числовые вклады
не накапливаются. Это данные mood.offset, без специального кода настроения.

## Раздражение (2026-11-03)

social.bad_conversation выдаёт каждой стороне irritation («Раздражение») в одном
30%-пакете с записью личного дневника. Вклад mood.offset−10 на120 игровых минут.
Отдельный тип не открывает VENT_ANGER: это действие по-прежнему требует angry.
Используются обычный singleton refresh до now+120 и существующий кэш истечения,
без накопления одинаковых вкладов и без новой динамики настроения.
